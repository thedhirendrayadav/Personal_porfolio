00 / FIELDWORK PROTOCOL

How to read the work.

Every case file separates what exists, what it demonstrates, and what still needs hardening. The goal is a portfolio that can be inspected rather than a gallery of unsupported claims.

01 / EVIDENCE MODEL

Claim → source → boundary.

Project statements are connected to source records, schemas, tests, captures, or reports. Constraints remain visible so a prototype is never presented as a production deployment.

  • CLAIMWhat the system is intended to show
  • SOURCEWhere the statement can be checked
  • BOUNDARYWhat is explicitly outside the evidence

02 / STATUS LANGUAGE

Progress without ambiguity.

Prototype marks an interaction or architecture under validation. Research System marks an investigative workflow. In Development marks active construction without a finished-production claim.

03 / DELIVERY LOOP

Small slices, visible behavior.

Work begins with the user, assets, and trust boundaries; moves through the smallest testable architecture; and ends with evidence, operating signals, and a clear next-hardening list.

Security is treated as a delivery constraint from the first model—not a final checklist.
